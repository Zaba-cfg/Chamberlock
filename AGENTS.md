# AGENTS.md

## What This Is

Unity 6.3 LTS 2D Roguelite. C#. URP 2D render pipeline. No CLI build system -- everything runs in the Unity Editor.

## Conventions

- **Namespaces mirror folder paths**: `Components.Weapons`, `Components.Base.HealthRelated`, `Entities.Player`, `Interfaces`, etc.
- **Composition over inheritance**: Entities (`Player`, `Enemy`) are thin shells. Behavior lives in `[RequireComponent]` MonoBehaviours.
- **ScriptableObjects for data**: Weapon stats (`WeaponData`), fire strategies (`WeaponFireStrategy`), and modifiers (`ModifierDefinition`) are SO assets, not hardcoded.
- **Event lifecycle**: Subscribe in `OnEnable()`, unsubscribe in `OnDisable()`. All inter-component communication via C# `Action` events.
- **Interfaces**: `IMoveInput`, `IInteractable`, `IModifierProvider` -- all minimal (1-2 members).
- **Naming**: `_camelCase` for private serialized fields, PascalCase for public members and methods.
- **No code comments**: Do not write comments in C# code (including XML doc comments). If something needs explaining, document it in `ARCHITECTURE.md` — describe what the script does and why.

## Architecture (quick reference)

- `Scripts/Interfaces/` -- contracts (`IMoveInput`, `IInteractable`, `IModifierProvider`)
- `Scripts/Entities/` -- composition shells (`Player`, `Enemy`)
- `Scripts/Components/Base/` -- reusable domain-agnostic components (Health, Movement, LookDirection, Interaction)
- `Scripts/Components/Weapons/` -- weapon system (Strategy pattern for fire behaviors)
- `Scripts/Components/Modifiers/` -- stat modifier pipeline (Add-then-Multiply calculation)
- `Scripts/Components/Enemy/` -- AI state machine (Chasing / SeekingWeapon / Attacking)
- `Scripts/Components/PlayerInput/` -- Unity Input System bridge
- `Scripts/Systems/` -- global services: `Pool/` (object pooling) and `Game/` (game state, run tracking, scene loading)
- `Scripts/Debug/` -- debug loggers and testers

## Key Patterns

- **Strategy**: `WeaponFireStrategy` (abstract SO) -> `MeleeFireStrategy`, `ProjectileFireStrategy`
- **Observer**: C# `Action` events on Health, Weapon, WeaponHolder, ModifierInventory
- **Pipeline**: Modifiers transform `WeaponFireContext` before strategy execution
- **State**: `EnemyBehavior` FSM with 3 states
- **Singleton service**: `PoolManager`, `GameManager`, `RunManager`, `SceneLoader` -- one instance, fail-fast guard, persistent where needed (`DontDestroyOnLoad`)

## Gotchas

- Always press Play from the `Bootstrap` scene (Build Settings index 0). `MainMenu` and `Gameplay` must also be in Build Settings. Playing them directly leaves the persistent managers (`GameManager`, `RunManager`, `SceneLoader`) null -- they are created in `Bootstrap`.
- No `.asmdef` files -- all scripts compile into the default `Assembly-CSharp`.
- No unit tests yet. `com.unity.test-framework` is imported but unused.
- No CI/CD, no linter, no formatter configured.
- `PlayerInputActions.cs` is auto-generated by the Input System package -- do not edit manually.
